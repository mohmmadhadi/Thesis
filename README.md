# Social Media Analysis

This repository contains a notebook-based social media analysis project that is being refactored into a reusable Python package. The original notebooks are preserved as analysis and reporting notebooks. Reusable logic is being extracted incrementally into `src/social_analysis/`, with lightweight tests and runnable pipeline scripts added around the extracted components.

The project analyzes simulated social media conversations, including exploratory data preparation, sentiment and emotion analysis, conversation dynamics, response coherence, topic modeling, user clustering, and echo chamber metrics.

## Environment Setup

Use Python 3.10 or 3.11. The project metadata currently declares:

```text
>=3.10,<3.12
```

Create and activate a virtual environment:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

On macOS/Linux:

```bash
source .venv/bin/activate
```

## Installation

Install the package in editable mode with the notebook and model dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e .
```

Some steps use NLTK resources. If they are not already available locally, download the required corpora/tokenizers before running topic modeling or user clustering:

```python
import nltk
nltk.download("punkt")
nltk.download("stopwords")
nltk.download("wordnet")
```

Transformer, sentence-transformer, BERTopic, BERTScore, UMAP, HDBSCAN, and Louvain dependencies are included because they are used by the extracted notebook logic.

Scripts resolve these paths relative to the project root and avoid hardcoded absolute paths.

## Data Requirements

The first pipeline step expects a SQLite simulation database:

```text

```

The EDA step reads this database and writes downstream CSV inputs to `data/processed/`, including:

```text

data/processed/mentions.csv
data/processed/reactions.csv
data/processed/post_hashtags.csv
```

Later scripts expect these generated files plus intermediate outputs from earlier steps. No data files are committed or generated by this README.

## Models Used

The current config and extracted modules reference these models:

- Sentence embeddings: `sentence-transformers/all-MiniLM-L6-v2`
- Echo chamber stance embeddings: `all-MiniLM-L6-v2`
- Cross-encoder: `cross-encoder/stsb-roberta-base`
- Transformer sentiment: `cardiffnlp/twitter-roberta-base-sentiment-latest`
- Emotion classifier: `j-hartmann/emotion-english-distilroberta-base`
- BERTScore model: `roberta-large`
- BERTopic embedding model: `all-MiniLM-L6-v2`

Model downloads are performed by the underlying libraries when the relevant scripts/classes are run for the first time.

## Testing

Run the lightweight test suite:

```bash
python -m pytest
```

The tests focus on deterministic behavior and mocked components. They intentionally avoid downloading transformer models, running notebooks, training heavy models on real data, or requiring large files.

## Reproducibility Notes

- Central paths and selected parameters are stored in `configs/default.yaml`.
- The repository is moving from notebooks toward tested package modules in `src/social_analysis/`.
- Some extracted classes preserve notebook constants directly, including thresholds, model names, score weights, and column names.
- Scripts should be run from the project root.
- Heavy model outputs may vary slightly across dependency versions, hardware, and downloaded model revisions.
- `reference_outputs/` is reserved for documented reference artifacts when notebook outputs can be generated and compared.

## Current Limitations

- The original notebooks remain the source analysis/report documents and are intentionally preserved.
- The runnable scripts are initial orchestration wrappers and are not yet fully validated end to end on the full dataset.
- Plotting and interactive visualizations from notebooks are only partially extracted.
- Some package modules still rely on heavy optional dependencies at runtime.
- `src/social_analysis/eda.py` and `src/social_analysis/utils.py` are placeholders.
- The echo chamber notebook filename is currently `07_eco_chamber.ipynb`.
- No generated results should be assumed to exist until the scripts are run locally with the required input data.
